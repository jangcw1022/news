## 1. 프로젝트 개요

### 1.1 목적
네이버 뉴스 검색 API를 활용해 키워드 기반으로 뉴스를 빠르게 검색하고, 최신순/정확도순으로 훑어볼 수 있는 개인용 뉴스 검색 서비스를 만든다.

### 1.2 타겟 사용자
- 특정 키워드(기업, 이슈, 인물 등)의 뉴스를 빠르게 모아보고 싶은 개인 사용자
- 포트폴리오 관람자 (기술 데모 목적)

### 1.3 핵심 가치
- 군더더기 없는 검색 경험 (검색 → 결과 → 정렬)
- 빠른 재검색을 돕는 인기 키워드 칩
- 로딩/빈 결과/에러 상태까지 빠짐없이 설계된 완성도

## 3. 아키텍처 개요 — API 키 보안이 핵심

네이버 오픈 API는 요청 헤더에 `X-Naver-Client-Id`, `X-Naver-Client-Secret`을 실어 보내야 한다. **클라이언트(브라우저)에서 직접 이 API를 호출하면 개발자 도구 네트워크 탭에 키가 그대로 노출**되므로 반드시 서버를 한 번 거쳐야 한다.

```
[브라우저] → (자체 API) /api/news?query=... → [Next.js Route Handler] → (키 포함 요청) → [네이버 뉴스 API]
```

- 클라이언트는 `/api/news`라는 우리 서버의 API Route만 호출한다.
- 네이버 Client ID/Secret은 **Route Handler 내부(서버 사이드)에서만** 사용되며 클라이언트 번들에는 절대 포함되지 않는다.
- 이 구조가 지켜지지 않으면(예: 클라이언트 컴포넌트에서 직접 fetch) 키가 유출되므로, 개발 시 반드시 `app/api/news/route.ts` 형태의 서버 라우트를 통해서만 네이버 API를 호출하도록 한다.

## 4. 환경변수 및 Git 보안 설정

### 4.1 `.env.local` (실제 키 — 절대 커밋 금지)
```env
NAVER_CLIENT_ID=발급받은_클라이언트_ID
NAVER_CLIENT_SECRET=발급받은_클라이언트_시크릿
```
> `NEXT_PUBLIC_` 접두사를 붙이지 않는다. 접두사가 붙으면 Next.js가 클라이언트 번들에 값을 노출시키므로, 서버 전용 값은 절대 `NEXT_PUBLIC_`을 사용하면 안 된다.

### 4.2 `.env.local.example` (커밋 대상 — 키 형식만 공유)
```env
NAVER_CLIENT_ID=
NAVER_CLIENT_SECRET=
```

### 4.3 `.gitignore` 필수 항목
```gitignore
# env
.env
.env*.local

# next.js
/.next/
/out/

# dependencies
/node_modules

# vercel
.vercel

# misc
.DS_Store
*.log
```

### 4.4 체크리스트
- [ ] `.env.local`이 `.gitignore`에 포함되어 있는지 최초 커밋 전 확인
- [ ] `git status`에 `.env.local`이 뜨지 않는지 확인 후 `git add`
- [ ] Vercel 배포 시, Vercel 프로젝트 설정 → Environment Variables에 동일한 키를 직접 등록 (`.env.local`은 배포에 자동 반영되지 않음)

## 5. 핵심 기능 명세

### F1. 검색창
- 텍스트 입력 + 검색 버튼, Enter 키로도 검색 실행
- placeholder: "궁금한 키워드를 검색해보세요"
- 검색어 앞뒤 공백 제거, 빈 문자열 검색 방지

### F2. 인기 키워드 칩
- 검색창 하단에 클릭 가능한 칩 형태로 노출 (예: "AI", "부동산", "환율" 등)
- 클릭 시 해당 키워드로 즉시 검색 실행 및 검색창에 반영
- **가정**: 1차 버전은 정적으로 큐레이션한 키워드 목록 사용 (실시간 트렌드 API 연동은 범위 밖)

### F3. 기사 카드 리스트
- 카드 구성: 제목, 요약(description), 언론사/출처, 발행일, 원문 링크(새 탭)
- 네이버 API 응답의 `title`, `description`에 포함된 `<b>` 태그 등 HTML 하이라이트 태그는 제거하거나 안전하게 렌더링 (XSS 주의, `dangerouslySetInnerHTML` 사용 시 sanitize 필수)
- 카드 클릭 시 원문(`originallink` 우선, 없으면 `link`)으로 이동

### F4. 정렬 (최신순 / 정확도순)
- UI: 토글 버튼 또는 드롭다운
- 네이버 API `sort` 파라미터 매핑

| UI 표시 | API sort 값 |
|---|---|
| 정확도순 (기본) | `sim` |
| 최신순 | `date` |

### F5. 로딩 화면
- 검색 요청 중에는 카드 자리에 스켈레톤 UI(또는 스피너) 노출
- 검색창/정렬 버튼은 중복 요청 방지를 위해 로딩 중 비활성화

### F6. 결과 없음 화면
- 검색 결과 0건일 때 안내 문구 노출: "검색 결과가 없습니다"
- 하단에 인기 키워드 칩을 다시 제안해 재검색 유도

### F7. 에러 화면
- 네트워크 오류, 서버 오류(4xx/5xx), 네이버 API rate limit(429) 등을 구분해 사용자 친화적 메시지로 표시
- "다시 시도" 버튼 제공

| 상황 | 메시지 예시 |
|---|---|
| 네트워크 끊김 | "네트워크 연결을 확인해주세요" |
| 서버/API 오류 | "일시적인 오류가 발생했어요. 잠시 후 다시 시도해주세요" |
| 요청 한도 초과 | "요청이 많아 잠시 후 이용해주세요" |

### F8. 반응형 디자인
- 카드 그리드: 모바일 1열 / 태블릿(≥768px) 2열 / 데스크탑(≥1024px) 3열
- 검색창과 키워드 칩은 모바일에서 전체 너비로 확장, 칩은 가로 스크롤 처리

## 7. 내부 API 파라미터 (`/api/news`)

| 파라미터 | 타입 | 설명 |
|---|---|---|
| `query` | string (필수) | 검색어 |
| `display` | number | 한 번에 가져올 기사 수 (기본 10, 최대 100) |
| `start` | number | 시작 위치 (페이지네이션용) |
| `sort` | `sim` \| `date` | 정렬 기준 |

## 8. 비기능 요구사항
- **호출 한도**: 네이버 오픈 API는 애플리케이션당 일일 호출 한도가 있으므로, 초과 시 F7 에러 화면으로 안내 (정확한 한도는 네이버 개발자센터에서 발급받은 애플리케이션 기준으로 재확인 필요)
- **보안**: 4장에 명시한 서버 프록시 구조 필수 준수
- **접근성**: 키보드만으로 검색/정렬/키워드 칩 조작 가능, 카드에 적절한 대비/포커스 스타일 적용
- **SEO**: 검색 결과가 클라이언트 사이드에서 그려질 경우 SEO에는 불리함 — 포트폴리오/개인용 목적상 우선순위 낮음으로 가정

## 10. 확인이 필요한 사항 (이번 PRD에서 가정한 부분)
아래는 요청에 명시되지 않아 합리적으로 가정하고 진행한 항목입니다. 다르게 원하시면 말씀해주세요.

1. **스타일링**: Tailwind CSS로 가정 — 다른 방식(CSS Modules 등) 선호 시 변경 가능
2. **인기 키워드**: 정적 큐레이션 목록으로 가정 — 실시간 트렌드 API 연동을 원하면 별도 설계 필요
3. **DB 사용 여부**: 이번 프로젝트는 DB 없이 진행으로 가정 — 검색 기록/즐겨찾기 등 개인화 기능이 필요하면 Supabase 도입 논의 필요
4. **페이지네이션**: "더보기" 버튼 방식 vs 무한 스크롤 — 아직 미정
